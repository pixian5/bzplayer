# 构建发布与版本号

## 1. 三个脚本的职责

| 脚本 | 作用 | 关键点 |
|---|---|---|
| `scripts/fetch_vlckit.sh` | 下载/校验 VLCKit 到 `macos/Vendor/vlckit-spm/` | 校验 `VLCKIT.lock`（版本/URL/SHA/大小） |
| `scripts/build_macos_app.sh` | 打包 `.app` | 用法 `build_macos_app.sh <输出.app> <版本号> <构建目录>` |
| `scripts/install_macos_app.sh` | 安装到 `/Applications` 并启动 | 结束旧进程 → 重建 → `lsregister` → `open` |
| `deploy.sh` | 部署封装（支持 `--commit`） | 中文提交并 push `origin main` |

【结论】打包脚本会把 `VLCKit.framework` 复制进 `Contents/Frameworks`，并给可执行文件写 `@executable_path/../Frameworks` rpath，最后 `plutil -lint` 校验 `Info.plist`。
【避坑要点】**只拷贝 release 二进制不行**；必须用这两个脚本，否则 VLCKit 加载不到。
【依据/来源】`scripts/build_macos_app.sh` L85-108。

## 2. 安装脚本的版本来源与提交

【结论】`install_macos_app.sh` 用 `git describe --tags --abbrev=0` 取**本地最近 tag** 作为版本号；变量名 `NEXT_VERSION` 但**不递增、也不打新 tag**，且依赖本地是否 fetch 过 tags。
【避坑要点】它**默认不提交**；只有 `install_macos_app.sh --commit "中文说明"` 或 `./deploy.sh --commit "中文说明"` 才 `git add -A` + commit + push。
【依据/来源】`scripts/install_macos_app.sh` L25-32、L62-72。

## 3. GitHub Actions（CI）

【结论】工作流 `.github/workflows/build-and-release.yml`：push `main` 或手动 `workflow_dispatch` 触发；流程 = fetch VLCKit → `swift build -c release` → `swift test` → 打包 `.app` → （可选签名/公证）→ 建 DMG → 上传 artifact → **自动创建 tag 并发布 Release**。
【避坑要点】CI 版本规则是 **`version = GITHUB_RUN_NUMBER - 1`**，由 CI **自行推送 tag**（`softprops/action-gh-release@v2.3.3`）。因此：
- run number 统计**所有** workflow 运行（含失败/取消/重跑）→ **tag 会跳号**，版本号 ≠ "第几次有效修改"。
- 连续 push 可能并发触发多组构建（文档建议加 `concurrency` 取消旧构建）。
【依据/来源】`.github/workflows/build-and-release.yml` L33-39、L140-147；分析文档 P1-4。

## 4. 版本号三处不一致（已知问题，尚未统一）

【结论】当前有**多套独立版本来源**，实测确实不一致：
| 来源 | 机制 | 实测值 |
|---|---|---|
| 根 `VERSION` 文件 | 手工/规则递增 | `241` |
| 本地最新 git tag | CI 推送 | `v240` |
| 安装的 `/Applications/BZPlayer.app` | 取本地 tag | `240` |
| CI Release | `RUN_NUMBER - 1` | 独立计数 |
【避坑要点】改动源码后按用户规则 `VERSION +0.0.1`，但**它不等于实际构建版本**（构建版本由 tag 决定）。要统一需先选单一版本源（分析文档建议：`VERSION` 文件为准，或纯以 git tag 为准）。
【依据/来源】复核：`VERSION=241`、`git describe --tags= v240`、app 版本 `240`。

## 5. 签名与公证现状

【结论】本地安装与 CI 产物**默认 unsigned**：CI 仅在配置 `MACOS_CERTIFICATE_BASE64`/`MACOS_CERTIFICATE_PASSWORD`/`MACOS_SIGNING_IDENTITY` 后 `codesign`；再配置 `APPLE_API_KEY_*` 才 `notarytool submit` + `stapler staple`。
【避坑要点】secrets 未配置时用户首次打开需手动放行；生产分发前应补 Developer ID 签名 + 公证 + staple。
【依据/来源】CI L67-113 与 `readme.md` 重大说明。

## 6. 本地开发构建（不打包）

```bash
zsh scripts/fetch_vlckit.sh          # 首次必须
cd macos/BZPlayer && swift run        # 直接运行
```
