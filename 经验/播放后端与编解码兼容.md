# 播放后端与编解码兼容

项目用两个后端：**AVPlayer（系统原生）+ VLCKit 4（libvlc）**。按容器/编码路由，失败可回退，用户可手动切换。

## 1. 后端路由顺序（chooseBackend）

【结论】路由在 `PlayerViewModel.chooseBackend` 里按固定顺序**短路 return**，先命中的规则生效。
【避坑要点】新增判据前必须确认**没有被更早的 return 抢先**；顺序决定一切。
【依据/来源】`macos/BZPlayer/Sources/BZPlayerApp/PlayerViewModel.swift` L2296-2336。

| 顺序 | 条件 | 结果 | 位置 |
|---|---|---|---|
| 1 | 扩展名 ∈ mkv/avi/flv/wmv/webm/rmvb/ts/mpeg/mpg/ogg/... | `.vlc` | 2299-2305 |
| 2 | `audioDelayMs != 0`（音频延迟非 0） | `.vlc` | 2308-2310 |
| 3 | **「MP4 系列容器 + 原生不可解码音频」（mp3/mp1/mp2）** | **`.vlc`** | 2317-2319 |
| 4 | `hasAV1`（AV1 视频） | **`.native`（提前 return！）** | 2320-2322 |
| 5 | ffprobe 可用 → `shouldPreferVLC(ffprobeInfo:)` | `.vlc` | 2323-2326 |
| 6 | h264 且检测到解码错误 | `.vlc` | 2327-2331 |
| 7 | ffprobe 不可用 → `shouldPreferVLC(asset:)` | `.vlc` | 2332-2334 |
| 8 | 默认 | `.native` | 2335 |

> ⚠️ 第 3 项**必须排在第 4 项 AV1 之前**。AV1 分支是"提前 return"，音频判据若排在它后面，
> **AV1 视频 + MP3-in-MP4** 会被直接判成 `.native` → 静音且不报错。

## 2. 能力判定必须"编码名 + 容器/OTI"联合

【结论】只看 `codec_name` 判断系统框架能否解码，一定会漏判（MP3-in-MP4 就是典型）。
【避坑要点】`mp3` 在 `.mp3` 文件、MOV 的 `.mp3` 采样描述下安全；但在 MP4（`mp4a` box 内 OTI 0x6B）里**不安全**，必须走 VLC。
【依据/来源】`PlayerViewModel.swift` 白名单 `nativeSafeAudioCodecs` 曾把 `mp3` 当原生安全（L2396-2400）；修复后新增 MP4 系列容器判断（L2367-2410）。

## 3. AVFoundation 对 MP3-in-MP4 是"静默丢轨"（已复核案例）

【结论】AVFoundation 不支持 MP4 容器内的 MP3，解析音频轨时**静默剔除该轨**：不报错、`isPlayable` 仍为 true、`status` 也能到 `.readyToPlay`，但**声音直接消失**。
【避坑要点】基于"播放失败"的自动回退**永远不会触发**；必须显式 `loadTracks(withMediaType: .audio)` 数轨。
【依据/来源】样本 `/Users/x/Downloads/Nagram Desktop/ezgif.com-video-merger.mp4` 现场实测。

### 样本与对照实验（已实测复核）

样本：15,680,934 B；video `h264`/`avc1` 1920x1080 1613644bps；audio `codec_name=mp3`、`codec_tag_string=mp4a`、48000Hz、2ch、128001bps。

| 文件 | 音频编码 | 容器采样项 | AVFoundation 音频轨 | 结论 |
|---|---|---|---|---|
| 原始 `ezgif...mp4` | mp3 | `mp4a` | **0** | 原始问题 |
| `-c:v copy -c:a aac` 转 mp4 | aac | `aac` | 1（subtype `aac `） | MP4 容器本身没问题 |
| `-c copy` remux 成 `.mov` | mp3 | `.mp3` | 1（subtype `.mp3`） | 同一 MP3 码流换容器即可识别 |

AVURLAsset 实测：`totalTracks=1`、`videoTracks=1`、**`audioTracks=0`**、`isPlayable=true`。
→ **同一 MP3 码流：放 MP4 丢轨、放 MOV 正常**。

## 4. 当前实现的判据（已下沉 Core，可单测）

【结论】判据已抽到 **`Sources/BZPlayerCore/BackendRoutingCore.swift`**：扩展名属 mp4/m4v/m4a/3gp/3g2/f4v 且 `codec_name ∈ {mp3, mp1, mp2}` → 走 VLC。`PlayerViewModel` 只做调用，不再自己维护一份。
【避坑要点】
- 这**不是**根因文档建议的 `codec_tag == "mp4a"`；两者对已知样本与 MOV 对照结论一致。
- 纯 `.mp3` 文件容器不是 MP4 系列，**不受影响**，仍走原生。
- 判据放 Core 是为了能被 `Tests/BZPlayerTests/BackendRoutingTests.swift`（11 个用例）锁住；**改判据必须同步改测试**。
【依据/来源】`BackendRoutingCore.mp4FamilyAudioNeedsVLC(containerExtension:audioCodecs:)`、`isMP4FamilyContainer`；App 侧入口 `mp4FamilyAudioNeedsVLC(url:ffprobeInfo:)`（L2383-2395）。

## 5. 原残留缺口 (a)(b) —— 已修（2026-10-17）

【结论】以下两项曾长期为真实缺口，现已修复，勿再按"未修"处理：
- (a) ~~ffprobe 缺失时修复失效~~ → **已修**：ffprobe 缺失且容器属 MP4 系列时，以 `audioTracks.isEmpty` 为信号走 VLC（依据：该类文件实测音轨被丢弃为 0）。代价：真正无音轨的 MP4 在 ffprobe 缺失时也走 VLC（能播，仅功耗略高）。
- (b) ~~AV1 早退绕过音频判据~~ → **已修**（见第 1 节顺序表）：把 MP4+不安全音频判据提到 `hasAV1` 分支之前，AV1 原生优先策略保留。
【避坑要点】修 (b) 只能调整路由顺序，**不要删 AV1 分支**（那是为硬件解码省电）。
【依据/来源】修复记录 [20261017-0010](../docs/20261017-0010-后端路由代码审查与四项修复补齐-hy3.md)。

## 6. ffprobe 是外部依赖

【结论】ffprobe 从 `/opt/homebrew/bin`、`/usr/local/bin`、`/usr/bin` 查找，**非应用内置二进制**；缺失时媒体分析**静默跳过**，兼容性诊断能力下降。
【避坑要点】分析最多等 8 秒、ffmpeg 解码诊断最多 20 秒，超时会终止子进程，不应阻塞播放启动。
【依据/来源】`readme.md` 重大说明。

## 7. 排查"有画面没声音"标准动作

1. `ffprobe -show_streams` 看每路 `codec_name` 与 `codec_tag`。
2. `AVURLAsset.load(.tracks)` 数 `audioTracks`（`isPlayable`/`readyToPlay` **不代表**有音轨）。
3. 做"只改封装"对照（`-c copy` 转 `.mov`）确认是否容器问题。
4. 确认后端：信息面板"建议播放后端"应显示 VLC；`audioTrackMenuEntries()` 仅在 VLC 后端下非空（原生后端右键恒显示"无可用音轨"）。

## 存疑/未验证

- 根因文档建议判据为 `codec_tag == "mp4a"`，但项目实际实现用"扩展名 + codec_name"。两者对已知样本/对照一致，但**未做全面对比验证**，不排除边界组合（如 `m4a`、`3gp` 内的 mp3）差异。
- `mp4a + esds OTI = 0x6B` 的 box 结构细节来自 docs 文档，**本次未独立复核**（仅 ffprobe 的 `codec_tag_string=mp4a` 已复核）。
- 是否还有其它"容器×编码"组合在 AVFoundation 下失声（如 MP3-in-MOV、特定 ADPCM 封装）**未验证**。
- docs 文案"AVFoundation 未识别音轨会自动切 VLC"在首轮修复前**并未真正实现**；补齐后对已知场景生效，ffprobe 缺失路径也已兜底。
- **「AV1 视频 + MP3 音频」只是按规则推导修好**（判据提到 AV1 之前），**未用真实 AV1+MP3 样本实测**。
- **「ffprobe 缺失」路径同样是按 `audioTracks=0` 推导**，未在真正卸载 ffprobe 的机器上跑过。
- 测试只覆盖 `BackendRoutingCore` 的纯函数；`chooseBackend` 本身（含异步 AVAsset 调用）**仍无单测**。
