# 仓库与文档规范

## 1. 文档命名规范

【结论】`docs/年月日-时分-标题-具体模型.md`，例：`20261016-2247-AV内核MP3-in-MP4强制走VLC修复-hy3.md`。
【避坑要点】早于规范的旧文档可能**缺模型名或时分**（如 `202609292334...未标注.md`），属遗留，不要机械重命名。
【依据/来源】`docs/README.md`、根 `文档索引.md`。

## 2. readme 必备章节与文档体系

【结论】根 `readme.md` 必须包含【当前开发进度】【下一步待实现】两节：README 里写简单说明，详细内容写入 `docs/` 的 `年月日-时分-当前开发进度-你的模型名.md`、`年月日-时分-下一步待实现-你的模型名.md`，并在 readme 中**指向这两个文件**。
【结论】根目录还需 `文档索引.md`：逐个介绍 `docs/` 里每个文档；readme 指向它。
【依据/来源】用户规则 + 现有 `readme.md` / `文档索引.md` 结构。

| 文件 | 作用 |
|---|---|
| `readme.md` | 概览 + 进度/待办摘要 + 运行/构建说明 + 文档索引表 |
| `文档索引.md` | 逐条介绍 `docs/` 每个文档及其时效性 |
| `经验/` | 把 docs 分类提炼成已核对的经验（本目录），readme/索引已指向 |

## 3. 重大问题与经验的沉淀

【结论】重大问题、操作、经验 → 在 `docs/` 建 `年月日-时分-标题-具体模型.md`；`经验/` 再做分类提炼。
【避坑要点】`docs/` 文档**不一定正确**（快照可能过时），分类进 `经验/` 时要复核或标注"存疑"。
【依据/来源】用户规则 + 本目录 README。

## 4. .gitignore 约定

【结论】以下不入库：
| 类别 | 条目 |
|---|---|
| macOS 元数据/日志 | `.DS_Store`、`*.log`、`datalog/` |
| SwiftPM/Xcode 构建态 | `.build/`、`.swiftpm/`、`DerivedData/`、`*.xcuserstate` |
| 本地产物 | `dist/`、`release/`、`artifacts/`、`*.dmg`、`*.app/`、`*.dSYM/` |
| VLCKit 大文件 | `macos/Vendor/vlckit-spm/`的 `.cache/`、`*.zip`、`VLCKit.xcframework/`、`__MACOSX/` |
| 工具/工作目录 | `.workbuddy/`、`.workbuddy-ai/`、`venv/`、`__pycache__/`、`node_modules/`、`.vscode/` |
【避坑要点】`VLCKit.xcframework`（解压约 2.6 GB）与 zip（约 861 MB）**绝不入库**；`.workbuddy-ai/` 与 `.workbuddy/` 同类，需一并忽略。
【依据/来源】根 `.gitignore`；修复文档提到已追加 `.workbuddy-ai/`。

## 5. 提交规范

【结论】用**中文 commit**；install/deploy 脚本只在显式 `--commit` 时提交并 push `origin main`。
【避坑要点】如需无提交，直接 `zsh scripts/install_macos_app.sh`（不带 `--commit`）。
【依据/来源】`scripts/install_macos_app.sh`；近期提交记录（`fix: ...`、`docs: ...` 中文）。

## 6. 版本号规则

【结论】每轮修改源码就把版本号 +0.0.1；新项目从 0.0.0 起。
【避坑要点】当前项目版本是**单一整数**（`VERSION`/tag），并非 major.minor.patch，且 `VERSION` 与实际构建版本脱节——详见「构建发布与版本号」。
【依据/来源】用户规则 + 实测。
